# Real Goal evaluation v1

Status: prepared, **not executed**. These are proposed evaluation inputs, not
successful searches, user research or verified opportunities.

## Execution and evidence

Use one immutable qualified candidate and a separate disposable local installation.
Record candidate version, commit, package hash, model/runtime and date before starting.
Create each Goal through the normal UI and separately confirm public read-only
research. Goal creation alone grants no network authority. Keep the same model,
limits and initial attempt policy across the cohort. Never automate purchases,
applications, messages or account access. No founder data or credentials in Git.

Keep one local row per proposed input with: evaluation ID, Goal ID/revision,
authorization time, mission IDs, outcome/block code, attempt count, first Find,
Evidence ID/hash, public source URL, fetched time, human feedback time, constraint
judgment and reason. Local API tokens and raw private stores stay local. Publish
only explicitly approved sanitized aggregate results.

Each retained Find must resolve to Kernel-fetched Evidence and SUPPORT. A reviewer
then separately checks every explicit constraint: price/currency, availability,
location, remote eligibility, skill, date and source credibility where applicable.
SUPPORT establishes subject relevance; it does not certify every commercial claim.
Classify constraint checks as met, failed or unknown. A missing price/date is unknown,
never an inferred success. Record shipping, tax and unit/hour ambiguity separately.

Mark useful/saved through existing feedback only after human review. Record honest
no-result, unsupported, inaccessible and technical failures. Do not replace failed
inputs with easier successes. Any Buscar más retry stays in the same Goal-revision
denominator; elapsed usefulness includes all retained attempts and review time.
Edited Goals start a separate revision and are not silent replacements.

## Reporting and decision

Report attempted/planned (N/30), unresolved inputs and all outcome counts. Report
Goal→useful rate with its numerator/denominator, median full wait and sample count,
technical failures, SUPPORT-without-constraint-proof, and met/failed/unknown
constraints by segment and language. Compare S01/S02 and W01/W02 without merging
their independent runs. Show spend/latency only if an actual usage record exists.

Provisional investigation triggers, not launch approval: any provenance/authority
violation blocks the evaluation; fewer than 6/10 useful Goals in a segment triggers
analysis of its dominant failure before expanding capabilities. These thresholds
are proposed engineering criteria, not validated market demand. Thirty selected
inputs from one installation cannot establish population retention or market fit.
Founder Windows UAT and public launch gates remain independent and outstanding.
