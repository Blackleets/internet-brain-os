# ROADMAP

Internet Brain OS / Hephaestus grows in controlled phases. Product speed never bypasses Kernel authority.

## MVP implementation status — 2026-08-09

Canonical local-first value loop:

```text
Goal → explicit read-only authorization → Capability/Risk Gate
→ safe discovery → Kernel source verification → Evidence
→ Opportunity/Find → persisted cross-surface truth
```

Durable controlled-memory authority remains behind the separate Memory Safety boundary.

### Foundation ✅

- Minimum Kernel: Case/Evidence, local storage, ingestion, Obsidian-compatible projection, tests.
- Browser Extension Copilot: authenticated loopback transport, public page capture, Forge/Missions/Finds/Models.
- Capability foundation: deny-by-default Registry, native `web.search` and `web.read`, Execution Engine policy routing.
- Knowledge foundation: entities/relationships/evidence links and local Kernel projections.
- Memory Safety v1: deterministic quarantine/recovery/prevention, terminal states remain terminal, exact replay safe and altered replay rejected.
- Monitoring foundation: scheduler/trigger/notification primitives behind Kernel authority.

### Goal-first operator experience ✅

- G0 Forge Focus and Goal-first shell.
- G1 Shared Goal Truth v1.
- G2 responsive Control Center on desktop + 390×844, keyboard/focus and reduced motion.
- G3 extension parser/transport/Living Forge/Goal chips consume the same Kernel-owned projection.
- Legacy Mission history remains compatibility telemetry, not Goal authority.

### G4 automatic authorized read-only loop ✅ implementation

Implemented and independently qualified layer-by-layer:

1. exact revision-bound read-only authorization receipt;
2. trusted interactive confirmation boundary; token/agent self-approval denied;
3. CapabilityRegistry + automatic policy before claim and lease;
4. authentic Hermes technically restricted to safe search-only discovery;
5. search output persisted as candidates, never Evidence;
6. private connectors runtime built/repaired by the Windows installer;
7. Kernel `web.read` re-fetches candidates through the SSRF-safe reader and rechecks authority before persistence;
8. only fetched page content may become Case/Evidence/Find;
9. one-click automatically continues discovery → verification without a second harmless-read prompt;
10. exact replay, lost-response and restart recovery remain idempotent and lease-safe;
11. web and extension consume the same Shared Goal Truth semantics.

G4 final candidate remains internal until the final immutable package matrix and manual UAT are complete.

### Distribution ✅ Windows MVP

- `Install Efesto.cmd` double-click setup/repair.
- Node.js 22+ and pinned pnpm repair when winget is available.
- Frozen-lockfile install.
- Trusted Shared, Kernel and connectors runtimes built before launch.
- Extension build, owner-local shortcut and self-healing launcher.
- Exact candidate SHA/package qualification on Windows 2022 and Windows 2025.
- No embedded or printed Kernel secrets.

### Supply-chain/release gate ✅

Mandatory on every affected candidate: architecture guard, strict production audit, typecheck, full tests, build, first-run, Chromium, Windows launcher/fresh-install and exact-package qualification. `publicLaunchApproved` stays false until manual UAT passes on the exact immutable candidate.

## Deliberately separate future slices

- automatic purchases or irreversible financial actions;
- login/form/message/file mutation without explicit capability approval;
- broad connector catalog before validated demand;
- arbitrary phone → PC remote Kernel authority;
- multi-tenant cloud brain/central telemetry;
- native mobile authority layer;
- public Skill/agent marketplace;
- decorative graph UI without Kernel-backed data.

Any recurring scheduling expansion, cross-device transport or irreversible action receives its own security/threat-model slice before changing authority.
